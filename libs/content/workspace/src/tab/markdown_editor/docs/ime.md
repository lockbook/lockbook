# IME
The target is **gorgeous, native, and standard** on each platform — Notes/Bear on iOS, the usual notes apps on Android, desktop chords on a hardware keyboard. In practice that means following subtle, poorly documented patterns so the system can draw the caret, loupe, selection handles, and menus for us. As this is an expensive contract to maintain, we aim for one implementation across the text stack — note, composer, single-line, and anything else editable.

Do what feels native on that device for focus:
* On **iPad**, a sidebar stays up and you might switch notes and keep typing, so staying first responder makes sense.
* On **iPhone** there is hardly anything else on screen while the keyboard is up besides back and dismiss-keyboard.

## Features
On **iOS**: autocorrect, swipe-to-type, dictation, and emoji from the system picker. On **macOS**: dictation is desired. On **iPad**: first class hardware keyboard support with desktop-like shortcuts while maintaining drag-scroll and other touch platform behaviors. On **Android**: similar classes of system typing (autocorrect, swipe, dictation).

## iOS host
The system text input is a `UITextInput` view (`TextInputView`) over the Metal editor, inside a page view (`TextPage`) that also holds a tap layer beneath it. UIKit draws and drives the caret, loupe, handles, menus, keyboard, and first responder; the editor owns the text, its layout, and the page scroll. Seven earlier attempts failed on the same foundations, so these are the rules.

**UIKit arbitrates every touch.** No raw touches reach the editor from the host, and no recognizer state is ever forced. A touch on one of the editor's touch targets (checkbox, fold, spoiler, link, image, scrollbar) is declined at hit-test time, so it lands on the tap layer and UIKit's text gestures never see it; a tap there applies the event the editor registered for the target, never a synthetic pointer event (egui has no cancelled press). The page's own pan and coast-stop see every touch, so a drag from a touch target scrolls and a touch during a coast only stops it. A list-item reorder is a long press that UIKit's text gestures must wait on.

**UIKit is the only writer of the selection for a touch.** The editor never places the caret in response to a touch, and never snaps or drops a write. UIKit's write for a tap applies at once and is reported with the selection-change pair, since the keyboard's spelling bubble and UIKit's double-tap menu are decided while the tap is still in hand; every write while a loupe or handle drag moves, UIKit's or the host's, is held and committed once at the lift, so the note neither reveals syntax nor reflows under the moving end, and the commit sends the same pair, which is when the keyboard recomputes autocapitalization and suggestions. UIKit's managed views (caret, handles, highlight) are laid out by the host each frame, since scroll and layout move geometry UIKit never hears of; while UIKit drags a handle or the loupe, only when the selection's ends moved on screen, since a layout resets the handle UIKit is placing. The spelling bubble's pick arrives as UIKit's private replacement action, answered as the previous host answered it. A loupe that sets the caret down where it was gets the menu; UIKit shows one only after a long loupe, and a slow tap on the caret is a short one.

**The editor owns the scroll.** The page pan and its release velocity feed the editor's scroll and momentum; a touch-down stops a coast; the scrollbar has its own recognizer; a handle, loupe, or floating cursor at the viewport's edge crawls the page from the host, since UIKit's own autoscroll is private. UIKit asks for the position under its handle or loupe caret as the finger moves, never while the finger is still, so while the page crawls the host re-asks the point UIKit last asked about, moves that end from the anchor fixed when the crawl began, and tells UIKit with a bare selection-did-change, which its highlight follows and which leaves the keyboard's context alone. A selection write from a finger on the text never reveals.

**Edits are synchronous.** A UIKit edit applies to the buffer at once, followed by an input-free layout frame, so the geometry UIKit asks for next is already right. Positions cross the boundary in UTF-16 units; the tokenizer is the editor's own, matched to Apple's word rules by fixture, and images and folds are single words, a link's words its own.

**Geometry is never missing.** A caret rect is never null; the rows holding the selection's ends are laid out even beyond the band around the viewport, so a handle drag re-anchors exactly. The find field takes keystrokes as egui events while it has focus; a read-only note uses UIKit's non-editable interaction with no keyboard; a masked field is secure text entry.
